## Decisions

- Electron Forge, React, TypeScript, Vite, Tailwind and editable shadcn-style primitives.
- Node's bundled SQLite avoids a second native ABI. Check the actual engine at startup and refuse unsafe versions.
- Business state lives in SQLite owned by the core, not React/localStorage.
- Main owns dialogs and OS-backed credential encryption. No stored secret is returned to the renderer.
- Built-in readers only. No shell or execution of imported code.
- Explicit demo mode, isolated from paid usage. No implicit mock fallback.
- Versioned workers/skills and run snapshots; permissions checked at each source read.
- Immutable usage entries in integer micro-USD; uncertain requests retain their reservation.
- Custom model IDs: fetch lists from each provider's native API or CLI, cache in SQLite, fail-open to a typed ID, never scrape HTML ([docs/model-list-fetch.md](model-list-fetch.md); COD-31 fetch+cache, COD-28 picker, and COD-30 deprecated chip).

- Backup code is in core/storage/backup.ts. Main owns file dialogs/read/write; the renderer cannot supply backup JSON or call internal backup commands. Imported newer revision history does not replace current worker content, and subsequent edits allocate above the highest saved revision to avoid collisions. - Checkpoints live in core/storage/checkpoints.ts and contain model messages/read IDs/step/reply phase. Leases are for the single local core; no distributed ownership or exactly-once provider guarantee is claimed.
- TeamRunner freezes queued role snapshots before the first async step, then binds committed join inputs before dispatch. Cancelled unused roles have records but no reservations/artifacts; the cancellation test now checks that actual dispatch invariant. - Native checker lives in `src/profiler`, launched by main in a disposable utility process. It receives selected-source copies and no credentials. The core remains the only SQLite writer. ## Desktop apps, phase 2b: borrowing the real mouse after asking, and the glow (COD-261)

`desktop_borrow_input` ([desktop.md](desktop.md#when-the-orglet-asks-to-borrow-your-mouse)) lets a solo chat's orglet ask to borrow the person's real mouse and keyboard. It covers up to five planned steps on one element (click, type, named keys, wheel), only when the background could not do it: a `not_possible` for that element earlier in the run, or no pattern for the step. The core refuses password fields, windows not granted, elevated apps, minimized windows and plans over the time limit. It checks everything with the helper (`borrow_check`, which sends no input) and asks on a card every time; a declined or stopped borrow is not asked again in that run. On Allow the helper runs the steps with `SendInput`, every input tagged as Orglet's own. Low-level hooks on a thread of their own treat any untagged input as the person's and stop the borrow before the next input (Escape is kept from the app). The helper re-checks the time limit (10 s) and the foreground window before every input, and the keyboard focus before typing and keys, then gives back the foreground and the cursor. It refuses when Windows shows the secure desktop. Journal rows keep the duration and how the borrow ended (`stopped` when the person ended it).

The glow (`core/tools/desktop-overlay.ts`, `main/desktop-overlay.ts`, `renderer/components/DesktopOverlay.tsx`) frames the window a background step acts on, and the whole display during a borrow. It uses the accent colour, fading from the edge to nothing, with a pill that shows the orglet's face, who is using what, and Stop. The window is one click-through, never-focusable overlay; the pill takes the pointer only while the pointer is over it. A borrow waits for main to confirm the glow is on screen (1.5 s at most, otherwise the helper shows a notice of its own). `OrgletCursor` replaces the live view's arrow and also rides on the glow. The browser's live view glows the same way while the orglet acts.

A live check (2026-09-27) found a false self-stop: Windows echoes Orglet's own tagged move to the element as an untagged move at that same point, and the hook took it for the person, so every borrow stopped in under 100 ms with nothing typed. Fixed by judging each untagged hook event against the points Orglet just aimed the cursor at, within a short window after Orglet's last send: an untagged move at (±2 px of) such a point, right after a send, is Orglet's echo, not the person; a move anywhere else, or any physical (never-injected) input, still counts. The rule is a pure function (`InputJudge`) the helper also exposes as a `classify` request, so a test drives it with recorded sequences and sends no input. The restore now uses a tagged `SendInput` move rather than `SetCursorPos`, and a flag stops any late hook event from turning a finished borrow into a stop.
